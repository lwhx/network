# 简化登录与升级说明

默认用管理员账号和密码登录。新用户首次初始化无需绑定验证器；初始化口令只用于第一次创建管理员。Cloudflare 账号默认展示一行，可按需添加更多账号。

## 记住登录

登录页默认勾选“记住登录（最长 30 天）”。实际期限由 `SESSION_TTL_DAYS` 控制，默认 30 天，最多 30 天。期限从登录时计算，刷新页面不自动延长。

- 勾选：Cookie 带期限，会话保存到 SQLite；关闭页面和容器重启后仍有效。
- 不勾选：使用会话 Cookie，会话只在面板进程内保存；容器重启后需重新登录。浏览器自身的窗口恢复功能可能保留会话 Cookie。
- 主动退出：服务端撤销当前会话，后续打开网页或重启面板也不能恢复该 Cookie。
- 变更 2FA：撤销全部旧会话，并为当前浏览器创建新会话。
- 重置管理员：旧认证版本失效，遗留 Cookie 不会因重建同名管理员而恢复。

## 可选验证器

新管理员默认密码登录。首次勾选“现在绑定验证器”时，需要生成密钥并输入验证码完成绑定。

已有账号的 2FA 在升级时保持开启。登录后点击顶部“登录设置”，输入当前密码和当前验证码，取消“启用验证器（2FA）”并保存，之后只需账号密码。

开启验证器时，输入当前密码，生成新密钥并加入验证器，再输入新验证码保存。开启或关闭都经过服务端重认证、CSRF、同源检查和限速。绑定密钥仅在经校验的绑定流程临时展示，不保存到浏览器持久存储或操作历史。

## 数据兼容

沿用原有 `/data/panel.sqlite` 和加密密钥，无需清空数据库。启动时自动添加 `panel_user.auth_revision` 和 `panel_sessions` 表，原密码和加密 2FA 字段保留。

会话表存储随机标识的 SHA-256 哈希、认证版本、CSRF token、所选 Cloudflare 账号和时间信息。Cookie 保存原始随机标识，不含管理员密码、API Key 或 2FA 密钥。

会话每次读取都核对用户认证版本和期限；会话更新只更新已有且仍有效的行，不会重新插入已撤销的会话。登录时使用验证当时的认证版本签发会话，避免与 2FA 修改交错时越过新的登录要求。

旧版会话只在内存中，升级后第一次需重新登录一次。后续记住登录跨重启有效。初始化口令、密码哈希、Cookie 安全属性和管理员重置流程继续保留。

## 验证范围

自动测试覆盖密码初始化、可选 2FA、真实旧数据库结构迁移、持久登录、未记住登录、过期、退出、多实例撤销竞争、2FA 修改与登录竞争、管理员重建、CSRF、页面字段与保存后状态请求失败。验证使用本地临时数据库与模拟 Cloudflare 数据，不操作真实账号。
